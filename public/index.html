Metro AFC Architecture & System Overview

Welcome to the Metro Automatic Fare Collection (AFC) & Apple Wallet Pass Platform — an end-to-end local simulation engineered to model modern contactless rapid transit ticketing.

🚇 1. Synthetic Network & Dijkstra Routing

The transit graph connects two lines: Blue Line (B1–B6) and Red Line (R1–R6) intersecting at Central Junction (CJ). Routes are computed using a stateful Dijkstra graph search where states track (station, current_line). In Fastest-Route mode, a 5-minute transfer penalty is applied whenever switching lines at an interchange.

💰 2. Server-Enforced Fare Slabs

Fares are computed on the server based on total route distance:

  • 0 to < 2 km: ₹10
  • 2 to < 5 km: ₹20
  • 5 to < 12 km: ₹30
  • 12 km or more: ₹40

🔒 3. HMAC-SHA256 Cryptographic Pass Verification

The QR pass encapsulates a minimal authenticated payload: { "tid": "TKT-...", "nonce": "...", "exp": 1234567890 }. The payload is signed with an HMAC-SHA256 signature using a server secret. No passenger names or financial data are stored inside the QR code.

🚧 4. Turnstile State Machine & Mobile Camera Scanning

Tickets follow strict atomic lifecycle transitions: ACTIVE ➔ IN_TRIP ➔ USED. The turnstile camera scanner runs locally using html5-qrcode with direct support for mobile phone cameras, torch toggle, and instant photo capture fallback.
